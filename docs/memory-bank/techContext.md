# Technical Context

## Tech Stack

### Core (Python)

- Python 3.10+
- `click` — CLI framework
- `requests` — HTTP client
- `jsonschema` — JSON Schema validation
- `semver` — semantic version parsing
- `json-logic-qubit` — JSON Logic rule evaluation
- `pyyaml` — YAML parsing
- `jinja2` — templating (HTML reports)
- `cookiecutter` — project scaffolding
- `python-gitlab` — GitLab API client
- `fastapi` + `uvicorn` — local dev server

### Documentation

- Plain Markdown under `docs/`, read on GitHub (no site, no Node toolchain)
- `json-schema-for-humans` — generates `docs/reference/schemas/` from `regis/schemas/` (`make reference`)

### State & Data

- JSON Schema validation
- JSON Logic rule evaluation
- Schema-driven analyzer and report payloads

### Testing

- `pytest` + `pytest-cov`
- `responses` — HTTP mocking
- `httpx` — async HTTP client in tests

### Dev Tools

- `ruff` — linting and formatting (rules in `[tool.ruff.lint]`, `pyproject.toml`)
- `mypy` and `import-linter` — typing and hexagonal layer boundaries
- `make` — the common CI contract (`make lint|test|security|image|reference`)
- `uv` — Python dependency management (lockfile: `uv.lock`, dev deps in PEP 735 `[dependency-groups]`)
- Renovate (self-hosted, `renovate.yml`) — dependency updates, configured by the socle's `.github/renovate.json5` (replaces Dependabot + manual `pinact` runs).
- `setuptools-scm` — version from git tags

## Development Environment

### Prerequisites

- Python 3.10+
- `uv`
- `make`; Docker for `make image`

### Setup Commands

```bash
# Python deps
uv sync

# CLI locally
uv run regis --help

# What CI runs
make lint        # ruff, mypy, import-linter, docs/reference up to date
make test        # pytest with coverage gates
make security    # pip-audit, HIGH gate
make image       # build and smoke-test both image variants
make reference   # regenerate docs/reference (rules and schemas)

# Fast test loop (no coverage gates)
uv run python -m pytest --no-cov

# Format
uv run ruff format .
```

## Build & Deploy

- GitHub Actions workflows in `.github/workflows/`: the common socle (`ci`, `pr-title`, `release`, `renovate`, `settings`, `socle-drift`) plus repo-specific `extra-*.yml` — see `systemPatterns.md` § CI/CD
- Release Please — automated changelog and releases (`release.yml`)
- `release.yml` — publishes the image variants of `.github/images.json` to GHCR with buildx provenance + SBOM, signed keyless with cosign
- No documentation site: GitHub renders `docs/` directly
- Workflows that write use the `oci-ci-ttc` GitHub App token (`CI_APP_CLIENT_ID` + `CI_APP_PRIVATE_KEY`); read-only jobs may use the default `GITHUB_TOKEN`
