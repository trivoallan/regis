# Design: Per-run registry cache (caching ImageInspector)

## Problem Statement

During a single `regis analyze` run, ~7 analyzers independently call
`get_manifest(reference)` for the same image (~15 `get_manifest` call sites
across the domain), and `oci.py` calls `get_manifest(ref)` twice for the same
ref per platform. Each call shells out to `regctl` (a subprocess + a network
round-trip). There is no run-scoped cache: a fresh `RegctlImageInspector` +
`RegistryClient` is built per analyzer in `AnalyzeImage._dispatch` (line 103).
The same manifest / config blob / tag list is therefore fetched N times per run.

## Why This Matters

Wasted wall-clock on every analysis, multiplied across the analyzer fan-out.
It matters most for the observe-first rollout (the registry-provenance roadmap
item): a central scan over 100+ images, or Regis added to 100+ CI pipelines,
pays this redundancy on every run. Deduping the registry reads is a direct cut
to the per-run cost with no behavior change. Note: the manifest-cache win is
**modest** (manifests/configs are small; the dominant cost is the full-image
pull paid twice by grype+syft — that is issue #806 part 2, see Scope).

## Scope

This design covers **only the registry cache** (issue #806 part 1). The
syft→grype SBOM handoff (issue #806 part 2 — avoid pulling the full image twice
across the `cve` and `sbom` analyzers) is **deliberately deferred to its own
design**: it changes the parallel-analyzer independence model (`cve` would have
to consume `sbom`'s output), which is a different kind of change and deserves
its own office-hours pass. See "Dependencies / Follow-up".

## Constraints

- **Hexagonal layering** (import-linter enforced): the cache is a driven
  adapter decorating the `ImageInspector` port; `core/` must not import it.
- **Thread safety.** Analyzers run under a `ThreadPoolExecutor` (default 4
  workers; `oci.py` opens a nested pool of up to 10). Today each analyzer gets
  its own inspector + `RegistryClient`, so nothing is shared. Sharing one
  caching inspector across the run means concurrent calls into one memo and one
  delegate — both must be safe.
- **Coverage gate**: per-file ≥90% (double gate). New adapter must be tested.
- **No behavior change**: the 14 analyzers must produce identical reports.

## Thread-safety analysis (load-bearing — verified against the code)

- **The delegate as currently wired (`RegctlImageInspector`) is stateless.** It
  holds only a `RegistryClient` for coordinates/creds and runs `regctl`
  subprocesses via `run_regctl`, which reads `client.username/password/
registry/repository` and shells out. It never touches mutable client state.
  Safe to call concurrently. ✅
- **CAVEAT — the underlying `RegistryClient` is NOT stateless**, and neither is
  the sibling HTTP adapter `RegistryImageInspector`: `RegistryClient` holds a
  mutable `requests.Session` and `_token` (mutated under `_authenticate` with no
  lock). `RegistryImageInspector` routes through those. **The cache decorator is
  therefore only safe over the regctl inspector as currently wired in
  `composition.py`. Do NOT place the cache over a shared `RegistryImageInspector`
  without first making that adapter thread-safe.** This constraint is documented
  in the adapter's docstring.
- **The lock's job is memo coherence + in-flight dedup, not delegate safety.**
  The delegate is independently thread-safe; the lock exists so the cache dict
  stays coherent under concurrent access and (optionally) so a duplicate
  in-flight fetch collapses to one.

## Premises (agreed)

1. The registry cache and the syft→grype handoff have different weight: the
   handoff is the bigger wall-clock win; the cache dedupes smaller `regctl`
   subprocess calls. **Agreed.**
2. The cache is clean and low-risk; the handoff is architecturally trickier
   (it breaks analyzer independence). Split them. **Agreed.**
3. No baseline measurement exists yet; the cache win should be verified
   (counting fake in tests + a manual before/after). **Agreed.**
4. Doing nothing leaves scans redundant on every run, penalizing the rollout
   perf budget. Real pain. **Agreed.**

## Approaches Considered

### Approach A: Caching inspector decorator (CHOSEN)

A `CachingImageInspector` that implements the `ImageInspector` port and wraps a
delegate inspector, memoizing all four read methods. Built **once per run** in
the composition root, shared across analyzers.

- Effort: S-M. Risk: Low-Med (thread safety — mitigated, see analysis above).
- Pros: clean decorator on a read-only port; dedupes the get_manifest calls AND
  `oci.py`'s double-fetch for free; does not touch the parallel model.
- Cons: leaves the bigger cost (image pulled twice by grype+syft) for part 2.
- Reuses: the `ImageInspector` port, the composition root, `FakeImageInspector`.

### Approach B: syft→grype SBOM handoff (deferred)

Generate the syft SBOM once, feed it to grype (`grype sbom:<file>`). The
dominant wall-clock win, but it breaks `cve`/`sbom` analyzer independence.
Deferred to its own design (issue #806 part 2).

### Approach C: Both at once (rejected)

Bundles the low-risk cache with the parallelism-touching handoff. Rejected in
favor of the incremental split ("make the change easy, then make the easy change").

## Recommended Approach

**Approach A.** Detailed design:

### New adapter

`regis/adapters/driven/registry/caching_image_inspector.py`:

```text
CachingImageInspector(ImageInspector)
  __init__(self, delegate: ImageInspector)
  # memoizes list_tags() / get_manifest(ref) / get_blob(digest) / get_digest(ref)
  # keyed by (method_name, args_tuple) — list_tags() keys on ("list_tags", ()).
```

**Memo design — start simple (single lock), measure before optimizing:**

- A single `threading.Lock` guards a plain `dict` keyed by `(method_name,
args_tuple)`. Get-or-compute holds the lock across the whole check→delegate→
  store. This serializes distinct misses, but the deduped set of refs per image
  is small and bounded, so contention is negligible. This is the YAGNI-correct
  default — simplest correct thing.
- **Deferred optimization (do NOT build now):** per-key locking (a lock per key
  so distinct refs fetch concurrently while same-key collapses) only if a
  measurement shows the single-lock serialization is a real cost. The bounded
  workload does not justify it up front.

Caching policy:

- **Successes only.** Exceptions propagate and are **not** cached (a transient
  failure for one analyzer must not poison the others; the next caller re-tries).
- **Immutability invariant (REQUIRED).** The cache returns the _same_ object to
  every caller. Callers MUST treat returned manifests/blobs/tag-lists as
  read-only. This holds today (verified: analyzers read manifests, oci.py mutates
  only its local `result`), and "no behavior change" depends on it. Document the
  invariant in the adapter docstring; a future caller that mutates a returned
  value would corrupt the shared entry for all threads.
- **No eviction.** One image's analysis touches a small, bounded set of refs;
  a plain dict is fine. Deliberate ceiling, documented.
- **Per-run scope** (the cache lives only as long as the inspector instance,
  one per `run`), so there is no cross-run staleness.

### Wiring

- `AnalyzeImage`: build the inspector **once** at the top of `run` —
  `inspector = self._inspector_factory(image)` **before** the
  `with ThreadPoolExecutor(...)` block — so the `_timed` closure captures the one
  shared inspector. Pass it into `_dispatch(analyzer, image, inspector)` instead
  of calling the factory inside `_dispatch`.
- `run_one` is the only other factory call site (single analyzer; caching is a
  harmless no-op there, kept uniform).
- `run_and_evaluate` calls `self.run(...)` and inherits caching transitively —
  it does **not** call the factory itself. **Only `run` and `run_one` change.**
- `composition.py`: `_inspector` returns
  `CachingImageInspector(RegctlImageInspector(_client(image)))`.

The use-case still receives an `inspector_factory` (no signature break); it just
calls it once per run rather than once per analyzer.

## Open Questions

- **Negative caching:** decided — do NOT cache exceptions.
- None blocking.

## Success Criteria

- A counting extension of the existing `FakeImageInspector` (`tests/fakes.py`)
  proves each distinct `(method, args)` hits the delegate **at most once** per
  run, even under concurrent calls.
- `oci.py`'s double `get_manifest(ref)` collapses to one delegate call.
- Full suite green (882+ tests), behavior of all 14 analyzers unchanged.
- New adapter ≥90% per-file coverage; `lint-imports` (Hexagonal layering) KEPT.
- Manual before/after on a multi-arch image confirms a wall-clock reduction
  (verification step, not a CI gate).
