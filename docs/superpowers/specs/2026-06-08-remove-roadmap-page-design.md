# Design — Remove the obsolete Roadmap docs page

**Date:** 2026-06-08
**Status:** Approved

## Problem

The published Roadmap page
([`docs/website/docs/roadmap.md`](../../website/docs/roadmap.md), served at
`https://trivoallan.github.io/regis/docs/roadmap`) no longer matches reality.
Its planning tables — _Recently shipped_, _Near-term (v0.29.0)_, _Medium-term_ —
are stale (the project is now on v0.34.0). The page also carries _Stability
tiers_ and _Compatibility commitments_ content, but the decision is to remove
the page in full rather than salvage parts of it.

## Decision

Delete the current-version Roadmap page entirely.

## Scope

**In scope — delete:**

- `docs/website/docs/roadmap.md`

**Explicitly out of scope — leave untouched:**

- `docs/website/versioned_docs/version-v0.32.0/roadmap.md`
- `docs/website/versioned_docs/version-v0.33.0/roadmap.md`
- `docs/website/versioned_docs/version-v0.34.0/roadmap.md`

  Versioned docs are immutable historical snapshots
  (`docusaurus.config.ts`: _"versioned_docs are immutable"_). At each of those
  releases the roadmap was accurate; freezing it is the intended behavior. Each
  version's autogenerated sidebar stays internally consistent, so no broken
  links are introduced.

- `docs/memory-bank/roadmap.md` — internal planning file (memory bank), not
  published. Out of scope for "the page".

## Impact

- **No inbound links to fix.** Verified: nothing in the other docs, the navbar,
  or the footer references the roadmap page.
- **Sidebar is autogenerated.** The page is included via `sidebar_position: 1.6`
  with no explicit `sidebars.*` file, so deleting the file removes the entry
  automatically — no config edit required.
- **Build stays green.** No broken links result; `onBrokenLinks: "ignore"` is
  set regardless.

## Delivery

- Conventional commit: `docs: remove obsolete roadmap page`.
- Open a PR against `main`.
